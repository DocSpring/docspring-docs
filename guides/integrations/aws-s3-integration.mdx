This guide walks you through setting up AWS S3 integration to automatically upload generated PDFs to your own S3 bucket.

## Authentication Methods

DocSpring supports two methods of authentication for AWS S3:

<Tabs>
  <TabItem label="Role-based Authentication (Recommended)">
    Uses AWS Security Token Service (STS) to assume an IAM role in your AWS account. This is the recommended approach as it's more secure than sharing access keys.

    ### Create an IAM Role in Your AWS Account

    <Steps>
    1. In the [IAM console](https://console.aws.amazon.com/iam/home), create a role. For the trusted entity, choose another AWS account and enter the DocSpring AWS account ID: `691950705664`. Leave **Require external ID** unchecked, because DocSpring doesn't send an external ID when it assumes the role.
    2. Give the role a permissions policy that only allows `s3:PutObject` on your bucket:
    </Steps>

    ```json title="IAM Role Permissions"
    {
      "Version": "2012-10-17",
      "Statement": [
        {
          "Effect": "Allow",
          "Action": ["s3:PutObject"],
          "Resource": ["arn:aws:s3:::YOUR_BUCKET_NAME/*"]
        }
      ]
    }
    ```

    <Steps>
    3. Name your role (must include `docspring` in lowercase)
    4. After creating the role, edit its trust relationship (trust policy) so that only DocSpring's S3 upload user can assume it:
    </Steps>

    ```json title="Trust Relationship"
    {
      "Version": "2012-10-17",
      "Statement": [
        {
          "Effect": "Allow",
          "Principal": {
            "AWS": "arn:aws:iam::691950705664:user/service/docspring-s3-cross-account"
          },
          "Action": "sts:AssumeRole"
        }
      ]
    }
    ```

    <Steps>
    5. Copy the role's ARN. You'll enter it in DocSpring as the **AWS Role ARN**.
    </Steps>

    <Aside type="caution">
      The role name must include `docspring`. This is a security measure that prevents you from accidentally allowing us to assume any other roles in your account.
    </Aside>

  </TabItem>

  <TabItem label="Access Key Authentication">
    Uses AWS access keys directly. Here's how to set it up:

    ### Create an S3 Bucket

    <Steps>
    1. In the [S3 console](https://s3.console.aws.amazon.com/s3/home), create a bucket
    2. Choose a bucket name and select the correct AWS region
    </Steps>

    ### Create An IAM Policy With Limited Permissions

    <Steps>
    1. In the [IAM console](https://console.aws.amazon.com/iam/home), create a policy that only allows `s3:PutObject` on your bucket. You can paste this JSON into the policy editor:
    </Steps>

    ```json title="IAM Policy"
    {
      "Version": "2012-10-17",
      "Statement": [
        {
          "Effect": "Allow",
          "Action": ["s3:PutObject"],
          "Resource": ["arn:aws:s3:::YOUR_BUCKET_NAME/*"]
        }
      ]
    }
    ```

    <Steps>
    2. Name the policy, e.g. "DocSpringS3Uploads", and add a description, e.g. "Allows the DocSpring service to upload PDFs to our S3 bucket"
    </Steps>

    ### Create An IAM User With Limited Permissions

    <Steps>
    1. In the [IAM console](https://console.aws.amazon.com/iam/home), create a user, e.g. "docspring-s3-uploads". The user doesn't need console access.
    2. Attach the policy you just created directly to the user
    3. Create an access key for the user (in the user's security credentials)
    4. Copy the Access key ID and Secret access key, and save these for later. AWS only shows the secret access key once.
    </Steps>

  </TabItem>
</Tabs>

<Aside type="note">
  DocSpring only needs `s3:PutObject`. If your bucket encrypts objects with an
  AWS KMS key (SSE-KMS), also allow `kms:GenerateDataKey` on that key.
</Aside>

## Configure DocSpring Integration

1. In DocSpring, go to **Integrations → Manage S3 connections** ([US](https://app.docspring.com/account_integrations/aws_s3), [EU](https://app-eu.docspring.com/account_integrations/aws_s3))
2. Click **Create S3 Integration** (or **Create a new S3 integration** if you don't have one yet)
3. Fill in the configuration:

### Required Fields

- **Authentication Type**: Choose "Access Key" or "Role-based Authentication"
- **Bucket Name**: Your S3 bucket name
- **Region**: The AWS region where your bucket is located (e.g., "us-east-1")

For access key authentication:

- **Access Key ID**: Your AWS access key ID
- **Secret Access Key**: Your AWS secret access key

For role-based authentication:

- **Role ARN**: The ARN of the IAM role to assume

### Optional Configuration

- **Submission Type**: Choose which PDFs to upload:
  - Only Live _(default)_
  - Only Test
  - Both Live and Test

  Combined PDFs are uploaded with every setting.

- **Template IDs**: Comma-separated list of template IDs. Only submissions for these templates are uploaded.
- **Folder IDs**: Comma-separated list of folder IDs. Only submissions for templates in these folders (and their subfolders) are uploaded. When you set both Template IDs and Folder IDs, a submission is uploaded if its template matches either one. Leave both blank to upload submissions for every template. Combined PDFs aren't filtered by template or folder.
- **API Token IDs**: Comma-separated list to limit uploads to specific API tokens. Submissions created without an API token (for example from the dashboard or a web form) are still uploaded.

To stop uploading a kind of PDF, leave its path template blank. For example, leave **Object Key Template for Combined PDFs** blank to upload submissions but not combined PDFs.

## Path Templates

Customize where PDFs are stored in your bucket using [Liquid](https://shopify.github.io/liquid/) templates.

### Available Variables

- `account_id` - Your DocSpring Account ID (e.g., `acc_X3gQR5GN6tS6tcYgJs`)
- `template_id` - Template ID (e.g., `tpl_eGc5CmFbPnCCmerqsx`)
- `template_name` - Template name (invalid characters replaced with underscore)
- `submission_id` - Submission ID (e.g., `sub_Gbxesk7Xf52Pq3KgT9`)
- `timestamp` - Processing time (e.g., `20180509094531`)
- `date` - Date (e.g., `20180509`)
- `year` - Year (e.g., `2018`)
- `month` - Month, not zero-padded (e.g., `5`)
- `day` - Day, not zero-padded (e.g., `9`)
- `metadata.<key>` - Any metadata values

For combined submissions, `template_id`, `template_name`, and `submission_id` aren't available. Use this instead:

- `combined_submission_id` - Combined submission ID (e.g., `com_Zbetd3ayK4EK3J4Hf4`)

### Default Templates

New integrations start with these templates. A blank template skips that kind of upload.

```liquid
submission_path_template: "live/templates/{{ template_id }}/{{ submission_id }}.pdf"
test_submission_path_template: "test/templates/{{ template_id }}/{{ submission_id }}.pdf"
combined_submission_path_template: "combined_submissions/{{ combined_submission_id }}.pdf"
```

### Example Custom Templates

Organize by date and template:

```liquid
{{ year }}/{{ month }}/{{ template_name }}/{{ submission_id }}.pdf
```

Use metadata for organization:

```liquid
clients/{{ metadata.client_id }}/{{ date }}_{{ submission_id }}.pdf
```

<Aside type="caution">
  In `template_name` and metadata values, characters that S3 object keys
  shouldn't contain (such as double quotes and non-ASCII letters) are replaced
  with underscores. Spaces, `/`, and most punctuation are kept, so a `/` in a
  template name or metadata value creates a subfolder. ([See the AWS object key
  guidelines](https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-keys.html#object-key-guidelines-safe-characters))
</Aside>

## Verify Your Integration

1. Create a live submission through the API or web interface (or set **Submission Type** to include test submissions first)
2. Check your S3 bucket for the uploaded PDF
3. Check the submission's `actions` array in the API response:

```javascript
// The actions array will contain an aws_s3_upload entry
{
  "actions": [{
    "action_type": "aws_s3_upload",
    "state": "processed",  // "pending" before upload completes, "error" if it failed
    "error_message": null,
    "result_data": {
      "s3_region": "us-east-1",
      "s3_bucket": "your-bucket",
      "s3_key": "live/templates/tpl_123/sub_123.pdf",
      "s3_url": "https://your-bucket.s3.amazonaws.com/live/templates/tpl_123/sub_123.pdf"
    }
  }]
}
```

## Monitoring Uploads

### Using API Responses

Check if a PDF has been uploaded to S3:

```javascript
const pdfHasBeenUploadedToS3Bucket = (submission) => {
  if (submission["actions"].length === 0) return false;
  const action = submission["actions"].find(
    (a) => a.action_type === "aws_s3_upload",
  );
  return action && action.state === "processed";
};
```

If the upload fails, the action's `state` is `error` and its `error_message` explains why. Failed uploads are retried automatically.

### Using AWS S3 Event Notifications

Set up [S3 event notifications](https://docs.aws.amazon.com/AmazonS3/latest/dev/NotificationHowTo.html) to receive webhooks when PDFs are uploaded to your bucket.

## Troubleshooting

### Access Denied

- For access keys: Verify the IAM user has correct permissions
- For roles: Check the role's permissions and trust relationship
- For roles: Ensure the role name includes `docspring`

### Invalid Credentials

- For access keys: Ensure keys are correct and active
- For roles: Verify the role ARN and trust relationship

### Path Template Errors

- Unknown or misspelled variables render as empty text instead of causing an error. Check the `s3_key` in the action's `result_data` to see the key that was used
- Ensure the template syntax is correct (use double curly braces)

### Region Mismatch

- Confirm the region matches your S3 bucket's location

For additional help, contact DocSpring support.
