**"Data Types" are the type of data that you send in your API request.**

Data types can be different to the [Display Types](/docs/reference/field-display-types/) that you use to render data on the PDF.
For example, a boolean `true` or `false` value can be used to show or hide a check mark on the PDF.
Or if you set the display type to "Text", the field could display the text "true" or "false" (or any other values you configure.)

### Conditions

When a _String_ field is displayed as a _Check_ or _Shape_, you can define a Condition. The field is only displayed when its value matches the condition. ([Static check marks and shapes](/docs/reference/field-display-types/#static-check-marks-and-shapes) are always displayed.) The condition can be:

- _Equals_, _Contains_, _Starts with_ or _Ends with_ the condition's text, or the opposite: _Doesn't equal_, _Doesn't contain_, _Doesn't start with_ or _Doesn't end with_.
- _Matches regex_ or _Doesn't match regex_: the condition is a regular expression (see below).
- _Is blank_ or _Isn't blank_: whether the value is empty or has only spaces, tabs and line breaks. These conditions have no text.

On a visual form, clicking a check mark or shape with an _Equals_, _Contains_, _Starts with_ or _Ends with_ condition selects it, and sets the value to the condition's text. The others only show whether the value matches. Embedded visual forms need version 2.20.0 for the _Doesn't_, _Is blank_ and _Isn't blank_ conditions, and to match regex conditions as the PDF does.

A _Matches regex_ condition is an [RE2 regular expression](https://github.com/google/re2/wiki/Syntax). The value matches when the expression matches any part of it: use `^` and `$` to match the whole value, and start with `(?i)` to ignore case, as in `(?i)^(yes|y)$`. In a value with several lines, `^` and `$` match at the start and end of each line, and `\A` and `\z` only at the start and end of the value. `\w`, `\d`, `\s`, `\b` and classes like `[[:alpha:]]` only know ASCII characters: list accented letters in a class, as in `[a-zA-ZÀ-ÿ]`.

RE2 matches any expression in a time proportional to the length of the value, so no condition can slow down a PDF or a form. Visual forms and signature requests match with RE2's JavaScript version, and show the same check marks and shapes as the PDF. So that the two always agree, a regex condition can't use:

- Lookaheads or lookbehinds (`(?=...)`, `(?!...)`, `(?<=...)`, `(?<!...)`), backreferences (`\1`), atomic groups, conditionals or recursion, which RE2 doesn't have. For "not", use a condition like _Doesn't contain_ or _Doesn't match regex_.
- Unicode classes like `\pL` or `\p{Greek}`: list the characters in a class instead.
- `\B`, `\C` or `\Z` (RE2 doesn't have `\Z`: use `\z` for the end of the value).
- With `(?i)`, the few letters that the two versions of RE2 case differently (such as `ɤ`).
- More than 1,000 repeats of a part (`a{1001}`), including repeats inside repeats, or groups nested more than 100 deep. The whole expression can have up to 10,000 characters, counting a repeated part once for each repeat.
- Group names with characters other than the letters a to z and A to Z, digits and `_`, or two groups with the same name.

The template editor shows what's wrong under the condition as you type, and a template can't be saved with a regex condition that breaks these rules. The API's error says what to change.

## Number

A _Number_ field can be an integer or a float. When _Integer_ is checked, the value must be an integer. (No decimal places.)

When _Currency_ is checked, online forms show a currency input. When a _Number_ field is displayed as _Text_, _Decimal Places_ sets the number of fixed decimal places used to format the number. (Set it to `0` to round to the nearest integer.)

### Validations

You can define a Minimum and Maximum value. You can check the "Exclusive" checkboxes to exclude the given value from the range. For example:

- When "Exclusive Minimum" is checked: `value > Minimum`
- When "Exclusive Minimum" is not checked: `value >= Minimum`

In the following example, the value must be an integer. The value must be greater than `0`, and less than or equal to `1000`.

<Image src={numberOptionsImg} alt="Number Options" width={250} />

### Formulas

A _Number_ field can be a formula that performs a calculation. Formulas can reference other _Number_ fields.
View the [Formula documentation](/docs/template-editor/formulas/) for more information about formula syntax, operators, and functions.

<Image src={formulasImg} alt="Formula editor" width={250} />

### Conditions

When a _Number_ field is displayed as a _Check_ or _Shape_, you can define a Condition. The field will only be displayed when the value matches the condition. The condition predicate can be one of: _Equals_, _Greater or Equal_, _Greater_, _Less or Equal_, _Less_, or _In Range_.

## Boolean

A _Boolean_ value must be either `true` or `false`.

### Text

When a _Boolean_ field is displayed as _Text_, the text will be either "Yes" or "No". These strings can be configured for each field. You can also set default values in the template settings.

<Image src={booleanTextImg} alt="Boolean text settings" width={250} />

### Check or Shape

When a _Boolean_ field is displayed as a _Check_ or _Shape_, the field will only be displayed when the value is `true`.
When _Invert Boolean Condition_ is checked, the field will only be displayed when the value is `false` or missing.
([Static check marks and shapes](/docs/reference/field-display-types/#static-check-marks-and-shapes) are always displayed.)

## Date

_Date_ values must be a string formatted as: `YYYY-MM-DD`.

When _Include Time_ is checked, the value must be a timestamp formatted as: `YYYY-MM-DDThh:mm:ss.fffZ`.

Dates sent as numbers like `05/07/2024` are read day first (July 5), unless the template's [Parse Dates](/docs/template-editor/settings/#parse-dates-using-the-templates-date-format) setting is checked. Then they're read in the order of the template's default date format, so `05/07/2024` is May 7 for `%m/%d/%Y`.

A _Date_ field can be formatted using a format string. DocSpring supports the [`strftime` format directives from the Ruby programming language](https://apidock.com/ruby/DateTime/strftime).
Japanese calendar (wareki) directives are also supported, e.g. `%Jf` (`令和5年4月1日`) and `%JF` (`令和五年四月一日`).

The _Difference_ formats (_Difference: Years_, _Difference: Months_, _Difference: Weeks_, _Difference: Days_, and _Hours_, _Minutes_, or _Seconds_ when _Include Time_ is checked) show the number of whole units between the date and the time when the PDF is generated. Years and months are counted using their average lengths (365.2425 days and 30.436875 days), so a result can be one unit off close to an anniversary.

<Image src={dateOptionsImg} alt="Date field options" width={250} />

### Example

Some forms may have separate fields for month, day, and year. You could configure three fields that all share the name `date`, but use different format strings for each field:

- `%-m` for month
- `%-d` for day
- `%Y` for year

## Address

The _Address_ type can be used to show a text input that autocompletes an address.
Address autocompletion is powered by Google Maps.

The address is formatted as a single string.
If you need to render the address parts separately, create separate text fields for each
part (e.g. street, city, state, zip, country.)

## Image

An _Image_ value can be a Base64 encoded image, or a URL where the image can be downloaded. Images downloaded from a
URL can be up to 100 MB.

- Request with a Base64 encoded image:

```json
"photo": {
  "base64": "/9j/4AAQSkZJRgABAQEASABIAAD/2wBDAAgGB ..."
}
```

- Request with an image URL:

```json
"photo": {
  "url": "https://example.com/images/photo.jpg"
}
```

See the [Image Display Type](/docs/reference/field-display-types/#image) section for information about resizing and cropping images.

## Barcode

A _Barcode_ data type ensures that you submit a valid barcode.
The value can be rendered as a barcode image or as a string.

You must configure the correct barcode [symbology](https://en.wikipedia.org/wiki/Barcode#Symbologies) (type).
DocSpring supports the following symbologies:

- [EAN-13](https://en.wikipedia.org/wiki/International_Article_Number)
  - 12 digits _(the check digit is added)_, or 13 ending with the check digit _(it must be correct)_
  - _Pattern:_ `/^[0-9]{12,13}$/`
- [EAN-8](https://en.wikipedia.org/wiki/EAN-8)
  - 7 digits _(the check digit is added)_, or 8 ending with the check digit _(it must be correct)_
  - _Pattern:_ `/^[0-9]{7,8}$/`
- [UPC-A](https://en.wikipedia.org/wiki/Universal_Product_Code)
  - 11 digits _(the check digit is added)_, or 12 ending with the check digit _(it must be correct)_
  - _Pattern:_ `/^[0-9]{11,12}$/`
- [PDF417](https://en.wikipedia.org/wiki/PDF417)
  - Any ASCII character
  - _(No validation)_
- [Code 128](https://en.wikipedia.org/wiki/Code_128)
  - Any ASCII character
  - _(No validation)_
- [Code 93](https://en.wikipedia.org/wiki/Code_93)
  - Uppercase letters, digits, `- . $ / + % SPACE`
  - _Pattern:_ `/^[A-Z0-9\-\.\$\/\+% ]+$/`
- [Code 39](https://en.wikipedia.org/wiki/Code_39)
  - Uppercase letters, digits, `- . $ / + % SPACE`
  - _Pattern:_ `/^[A-Z0-9\-\.\$\/\+% ]+$/`
- [Code 25](https://en.wikipedia.org/wiki/Code_25)
  - Digits
  - _Pattern:_ `/^[0-9]+$/`

<Aside>
  Please contact support@docspring.com if you need a different symbology.
</Aside>

## Combined

_Combined_ fields allow you to combine multiple field values into a single string.

For example, you could combine `first_name` and `last_name` fields into a single `full_name` field:

<Image src={combinedFieldsImg} alt="Combined field example" width={250} />

Choose _Use Separator_ or _Use Format String_:

- _Separator_: Joins the values with any string (including an empty string.)
- _Format String_: A string containing numbered variables that start at `$0`, in the order of the _Combined Field Names_. Example: `Full Name: $0, Address: $1`

Each value is printed as its own field prints it: a date in the field's date format, a number with its decimal places, and a check box as its true or false text. A value is printed as written, even when it contains something like `$1`.
