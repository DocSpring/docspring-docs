Connect DocSpring to your apps and automation workflows to generate PDFs, collect signatures, and store completed documents.

## Getting started

For third-party apps, create a DocSpring API token and enter its token ID and secret in the app's connection settings. Cloud storage (AWS S3 and S3-compatible storage, Google Drive, Dropbox and Box) is configured in DocSpring, under **Integrations**. AI assistants connect to [DocSpring's MCP server](/docs/mcp/) and sign in to DocSpring instead of using an API token.

## When an integration fails

AWS S3, Google Drive, Dropbox and Box integrations upload each PDF in the background. When an upload fails, the submission's `actions` array shows the upload with `state: "failed"` and an `error_message`, and the integration's page in DocSpring shows it as failing, with the last error.

An upload that fails because of a problem on DocSpring's side, or a timeout or an error at Amazon S3 itself, shows `state: "error"` instead. DocSpring retries it, and it doesn't count as a failure of your integration.

- **Retries**: uploads that fail for a reason that can go away by itself (a timeout, a rate limit, an error at the storage provider, or an S3 bucket policy that denies access) are retried automatically. Others, such as a wrong access key or a deleted folder, aren't retried.
- **Emails**: DocSpring emails the account's billing user when an integration starts failing: on the first failure that needs you to fix something, or on the second failure in a row otherwise (at most one of these emails a day). If uploads are still failing a day later, you get a second email. Each email shows the last error and the last submission that failed to upload. To stop these emails for an integration, turn off **Email failure alerts** in its settings.
- **Automatic disabling**: if an integration's uploads have been failing continuously for 3 days, DocSpring disables it and emails you. Saving the integration's settings or reconnecting it starts the count again. While it's disabled, PDFs aren't uploaded, and they aren't uploaded later when you turn it back on. Disabling sends an `account_integration.updated` webhook event.
- **Turning it back on**: fix the problem, then open the integration's settings, turn on **Enabled** and save. Any successful upload clears the failing state.
