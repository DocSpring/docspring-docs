An assistant connected to [DocSpring's MCP server](/docs/mcp/) sees the tools that its access allows. You choose the
access when you sign in: **Read only**, **Read and write** or **Full access**.

Tools that make PDFs or set up templates wait until DocSpring has finished, like the
[synchronous API](/docs/api-guide/synchronous-requests/). When that takes longer than about 50 seconds, the tool
returns the record's ID with the state `processing`, and the assistant checks it again with `get_submission` or
`get_template`.

## Read only

Every connection has these tools.

## Read and write

Tools that change or remove what's already there, such as `update_fields`, `remove_fields` and `restore_version`, are
marked as destructive, so clients ask you to confirm each call. Tools that only add something, like `add_fields` or
`copy_template`, aren't.

Tools that can make DocSpring reach outside your account are marked as open-world: they download a link (a PDF, an image
in your data), send to a webhook's URL, email people, or check an email domain's DNS records. The tools that change or
copy a template are marked too, but only because an HTML template can link to images, fonts or stylesheets on the web,
which DocSpring loads when it renders the template's preview. With PDF and Word templates and page designs, they don't
load anything.

<McpToolTable scope="write" />

## Full access

Full access adds the tools that delete things, and the tools for webhooks and email actions.

### Delete

These tools can't be undone, so clients ask you to confirm each call.

<McpToolTable scope="delete" />

### Webhooks and email actions

An assistant sees and changes all of your webhooks and [email actions](/docs/template-editor/email-actions/), as you
can in DocSpring. `send_test_email` sends only to you. The webhooks and email actions an assistant sets up stay when
you disconnect it. Assistants never see a webhook's signing secret or its headers' values: copy the secret from the
webhook's page in DocSpring, and add headers there.
