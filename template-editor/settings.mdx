Click **Settings** in the template editor's top bar to change a template's settings. They're in tabs: **General**,
**PDF output**, **Forms**, **Submissions**, **Embedding**, **Webhooks**, **Field defaults** and **Advanced**. Each
setting below says which tab it's on.

The **Field defaults** tab sets the typeface, colors, date formats and other options that fields use when they don't
set their own.

## Locked

_On the General tab._ Locked templates cannot be changed or deleted. See [Locked Templates](/docs/template-editor/locked-templates/).

## Expire Submissions

_On the Submissions tab._ The _Expire submissions_ setting allows you to configure a data retention policy for your submissions.

- If _Expire submissions_ is **unchecked** (the default), we will store all submission data and generated PDFs indefinitely. (Nothing will ever be deleted automatically.)
- If _Expire submissions_ is **checked**, we will automatically delete all submission data and metadata, generated PDFs, any uploaded images, and the submitter's IP address, browser and location after a certain period of time. The expiration time is set beside it (_5 minutes_, _24 hours_, _7 days_, etc.)

A submission that fails (for example, with invalid data) is kept for at least 48 hours before it expires, even if the expiration time is shorter, so that you can see what went wrong and a retry still has its data.

(Please note that electronic signatures and a SHA256 hash of the PDF are always retained for UETA and ESIGN compliance.)

You can also [make an API request](/docs/api/#tag/submissions/delete/submissions/{submission_id}) to immediately expire a submission.

## Allow Additional Properties

_On the Submissions tab._ By default, the data that you submit must exactly match the JSON schema. Any additional properties will cause a validation error. This guarantees that you haven't forgotten to add any fields to your template, and it also guards against accidental field deletion.

When the **Allow additional properties in JSON data** setting is enabled, additional properties in your data will be silently ignored. This can be useful when you don't have full control over the JSON data (e.g. a webhook integration with a third-party service.)

## Encrypt PDFs with a Password

_On the PDF output tab._ When **Encrypt PDFs with a password** is checked, generated PDFs are encrypted with the
**PDF password**, and can only be opened by entering that password. (This is called a "user password".)

## Merge Audit Trail With Signature Request PDFs

_On the PDF output tab, for PDF templates only._ When checked, audit trail pages are appended to the generated PDF when a submission has signature requests. When unchecked, the audit trail PDF can be downloaded separately.

## Add Submission ID Footers to Signature Requests

_On the PDF output tab, for PDF templates only._ When checked, the submission ID is added to the bottom right corner of each page when a submission has signature requests.

## Parse Dates Using the Template's Date Format

_On the Field defaults tab, for PDF templates only._ This setting is under the default date formats (**Parse dates
using format**).

We recommend sending date values as `YYYY-MM-DD` (see [Date](/docs/reference/field-data-types/#date)). Dates sent as numbers like `05/07/2024` (with slashes, dashes or dots) are read day first by default, so `05/07/2024` is July 5, and a date like `05/13/2024` can't be read and is left blank.

When **Parse dates using format** is checked, these dates are read in the same order as the template's default **Date** format: month first for `%m/%d/%Y`, and day first for `%d/%m/%Y`. Fields that include a time use the default **Date/time** format. Dates sent as `YYYY-MM-DD` are read the same way either way.

Each template version keeps its own setting. If your template has published versions, publish a new version after changing it: API submissions use the latest published version by default (see [Template Versions](/docs/template-editor/versions/)).

You can also set this for new templates on your account's **Template defaults** page, and change it with the `parse_dates_using_template_date_format` option in the [templates API](/docs/api/#tag/templates).

## HTML Page Settings

_On the PDF output tab._ HTML templates have **Page format**, **Landscape**, **Width**, **Height**, margin and
**Print background** settings. See [Page Settings](/docs/html-templates/overview/#page-settings).

## Online Form Privacy

_On the Forms tab._ Set this to **Public** to allow anyone to fill out the online form if they have the URL.

## Online Form

_On the Forms tab, as **Form type**._ Which form a PDF template's online form link opens: the **web form** (questions on a page), the **visual form** (fields
filled in on the PDF), or **both**, in two tabs. A `mode` parameter in the link overrides it (see
[Web Form, Visual Form or Both](/docs/forms/web-forms/#web-form-visual-form-or-both)). HTML templates don't have this
setting: they have no visual form, so they always show the web form.

You can also set this on your account's **Template defaults** page, for new templates and, with **Update Templates**,
for existing ones. HTML templates stay on the web form either way.

## Show Continue Once Required Fields Are Filled In

_On the Forms tab, for PDF templates only._ Visual forms and signature requests have a **Next** button that takes the user through each field in
turn. By default, while the user is in a field, the **Continue** button only replaces it once every field has a value
or has been visited. Check
this setting to show **Continue** as soon as every required field is filled in, so users can skip the optional
fields. The `allowSkippingOptionalFields` option of [Visual Forms JS](/docs/forms/js-libraries/visual-forms-js/) and
[Signature Requests JS](/docs/forms/js-libraries/signature-requests-js/) overrides this setting either way.

## Submission Privacy

_On the Submissions tab._ Set this to **Public** to allow anyone to view submission data and download their PDF if they have the URL.

This is useful when you have added a [@@data_url QR code to the PDF](/docs/template-editor/field-names/#special-field-names).
(`@@data_url` is a URL where the submission data can be viewed or downloaded.)

## Webhook URL

Configure webhooks on the [Webhooks page](https://app.docspring.com/webhooks). See [Webhooks Overview](/docs/webhooks/overview/).

Existing legacy webhook URLs on templates and API tokens (shown on the **Webhooks** tab as **Legacy webhook URL**) keep working until they are migrated to the new webhooks system.

## Slack Webhook URL

_On the Webhooks tab._ Posts a message to a Slack channel whenever this template generates a PDF. Each message links to the PDF and to its
submission. Test PDFs and combined PDFs don't post a message.

To get a URL, create a Slack app with an incoming webhook for the channel
([Slack's guide](https://docs.slack.dev/messaging/sending-messages-using-incoming-webhooks)), then paste the webhook URL
into this field. Messages show your Slack app's name and icon.

## Redirect URL

_On the Forms tab._ We'll redirect users to this URL whenever they fill out the online form to generate a PDF.
This applies to online forms hosted on [docspring.com](https://docspring.com),
and [embedded forms on your own website](/docs/guides/embedded-forms/embedded-web-forms/).
The submission ID, template ID, and template name will be appended to the URL as query params.

## Template Description

_On the General tab._ The template description is shown under the template's name at the top of its [online form](/docs/forms/web-forms/), in
every mode, and is the page's meta description. It is not shown on embedded forms or signature requests.

## Embedded Template Editor Settings

These are on the **Embedding** tab.

- **Embed domains**: Not shown in the embedded editor. A comma-separated list of domains where you embed the template editor or signature request forms. The template editor accepts wildcards such as `*.example.com` and isn't restricted when the list is blank (see [Embed Domains](/docs/guides/embedded-template-editor/#embed-domains)). Live [embedded signature requests](/docs/guides/embedded-forms/embedded-signature-requests/) only load on the listed sites, accept the same wildcards and ports, and don't load on any site when the list is blank; test signature requests load anywhere.
- **Embed edit token**: Not shown in the embedded editor. The token you use with `template_editor.js` to embed this template editor. You can show or regenerate it. See [Embed Edit Token](/docs/guides/embedded-template-editor/#embed-edit-token).
- **Embedded editor permissions**: Not shown in the embedded editor. Allow embedded editor users to change template settings, to publish, restore, and delete versions, or to replace the PDF document. By default they can only edit fields and layout. See [Security](/docs/guides/embedded-template-editor/#security).
- **Predefined fields**: _PDF templates only._ The field names that embedded editor users can add. See [Use Predefined Fields](/docs/guides/embedded-template-editor/use-predefined-fields/).

## Template PDF

_On the General tab, for PDF templates only._ Shows the template's PDF file. Drop a new PDF onto the upload area to replace it. The template
keeps its fields.

To replace the fields too, check **Re-import fields from the new PDF** before you drop the new PDF. When the PDF has
been processed, all of the template's fields are replaced with the fillable fields in the new PDF, the same way as when
you first uploaded a PDF (the fields can't be edited until then). Fields you added or changed in DocSpring are removed.
The default typeface, font size, bold and color are taken from the new PDF's fields, and the template's other settings
are kept. Click **Undo** in the message that appears to put the previous fields and defaults back. If the new PDF has no
fillable fields, the template keeps its fields.

With the API, set `reimport_fields` to `true` when you
[update the template](/docs/api/#tag/templates/put/templates/{template_id}) with a new `document`. Without a new
`document`, the fields are re-imported from the template's current PDF. In our API clients, use the "Update a
template's document with a cached S3 file upload" operation (`updateTemplateDocumentFromUpload`), which has the
`reimport_fields` option. A re-import isn't allowed on a locked template.
