You can click the "Settings" button in the header to configure your template settings.

Configure default values for field options in the sidebar on the right.

## Locked

Locked templates cannot be changed or deleted. See [Locked Templates](/docs/template-editor/locked-templates/).

## Expire Submissions

The _Expire Submissions_ setting allows you to configure a data retention policy for your submissions.

- If _Expire Submissions_ is **unchecked** (the default), we will store all submission data and generated PDFs indefinitely. (Nothing will ever be deleted automatically.)
- If _Expire Submissions_ is **checked**, we will automatically delete all submission data and metadata, generated PDFs, any uploaded images, and the submitter's IP address, browser and location after a certain period of time. The expiration time can be configured in the template settings (_5 minutes_, _24 hours_, _7 days_, etc.)

A submission that fails (for example, with invalid data) is kept for at least 48 hours before it expires, even if the expiration time is shorter, so that you can see what went wrong and a retry still has its data.

(Please note that electronic signatures and a SHA256 hash of the PDF are always retained for UETA and ESIGN compliance.)

You can also [make an API request](/docs/api/#tag/pdf-submissions/delete/submissions/{submission_id}) to immediately expire a submission.

## Allow Additional Properties

By default, the data that you submit must exactly match the JSON schema. Any additional properties will cause a validation error. This guarantees that you haven't forgotten to add any fields to your template, and it also guards against accidental field deletion.

When the **Allow Additional Properties in JSON Data** setting is enabled, additional properties in your data will be silently ignored. This can be useful when you don't have full control over the JSON data (e.g. a webhook integration with a third-party service.)

## Encrypt PDFs with a Password

When **Encrypt PDFs with a Password** is checked, generated PDFs are encrypted with the **PDF Password**, and can only be opened by entering that password. (This is called a "user password".)

## Merge Audit Trail With Data Request PDFs

_PDF templates only._ When checked, audit trail pages are appended to the generated PDF when a submission has data requests. When unchecked, the audit trail PDF can be downloaded separately.

## Add Submission ID Footers to Data Requests

_PDF templates only._ When checked, the submission ID is added to the bottom right corner of each page when a submission has data requests.

## Parse Dates Using the Template's Date Format

_PDF templates only._ This setting is in the sidebar on the right, under the default date formats (**Parse Dates**).

We recommend sending date values as `YYYY-MM-DD` (see [Date](/docs/reference/field-data-types/#date)). Dates sent as numbers like `05/07/2024` (with slashes, dashes or dots) are read day first by default, so `05/07/2024` is July 5, and a date like `05/13/2024` can't be read and is left blank.

When **Parse Dates** is checked, these dates are read in the same order as the template's default **Date** format: month first for `%m/%d/%Y`, and day first for `%d/%m/%Y`. Fields that include a time use the default **Date/Time** format. Dates sent as `YYYY-MM-DD` are read the same way either way.

Each template version keeps its own setting. If your template has published versions, publish a new version after changing it: API submissions use the latest published version by default (see [Template Versions](/docs/template-editor/versions/)).

You can also set this for new templates in your account's template settings, and change it with the `parse_dates_using_template_date_format` option in the [templates API](/docs/api/#tag/templates).

## HTML Page Settings

HTML templates have **Page Format**, **Page Size**, **Page Margins**, and **Print Background** settings. See [Page Settings](/docs/html-templates/overview/#page-settings).

## Online Form Privacy

Set this to **Public** to allow anyone to fill out the online form if they have the URL.

## Online Form

Which form a PDF template's online form link opens: the **web form** (questions on a page), the **visual form** (fields
filled in on the PDF), or **both**, in two tabs. A `mode` parameter in the link overrides it (see
[Web Form, Visual Form or Both](/docs/forms/web-forms/#web-form-visual-form-or-both)). HTML templates don't have this
setting: they have no visual form, so they always show the web form.

You can also set this in your account's template settings, for new templates and, with **Update Templates**, for
existing ones. HTML templates stay on the web form either way.

## Show Continue Once Required Fields Are Filled In

_PDF templates only._ Visual forms and data requests have a **Next** button that takes the user through each field in
turn. By default, while the user is in a field, the **Continue** button only replaces it once every field has a value
or has been visited. Check
this setting to show **Continue** as soon as every required field is filled in, so users can skip the optional
fields. The `allowSkippingOptionalFields` option of [Visual Forms JS](/docs/forms/js-libraries/visual-forms-js/) and
[Data Requests JS](/docs/forms/js-libraries/data-requests-js/) overrides this setting either way.

## Submission Privacy

Set this to **Public** to allow anyone to view submission data and download their PDF if they have the URL.

This is useful when you have added a [@@data_url QR code to the PDF](/docs/template-editor/field-names/#special-field-names).
(`@@data_url` is a URL where the submission data can be viewed or downloaded.)

## Webhook URL

Configure webhooks on the [Webhooks page](https://app.docspring.com/webhooks). See [Webhooks Overview](/docs/webhooks/overview/).

Existing legacy webhook URLs on templates and API tokens (shown as **Legacy Webhook URL**) keep working until they are migrated to the new webhooks system.

## Slack Webhook URL

Posts a message to a Slack channel whenever this template generates a PDF. Each message links to the PDF and to its
submission. Test PDFs and combined PDFs don't post a message.

To get a URL, create a Slack app with an incoming webhook for the channel
([Slack's guide](https://docs.slack.dev/messaging/sending-messages-using-incoming-webhooks)), then paste the webhook URL
into this field. Messages show your Slack app's name and icon.

## Redirect URL

We'll redirect users to this URL whenever they fill out the online form to generate a PDF.
This applies to online forms hosted on [docspring.com](https://docspring.com),
and [embedded forms on your own website](/docs/guides/embedded-forms/embedded-web-forms/).
The submission ID, template ID, and template name will be appended to the URL as query params.

## Template Description

The template description is shown under the template's name at the top of its [online form](/docs/forms/web-forms/), in
every mode, and is the page's meta description. It is not shown on embedded forms or data requests.

## Embedded Template Editor Settings

- **Embed Domains**: Not shown in the embedded editor. A comma-separated list of domains where you embed the template editor or data request forms. The template editor accepts wildcards such as `*.example.com` and isn't restricted when the list is blank (see [Embed Domains](/docs/guides/embedded-template-editor/#embed-domains)). [Embedded data requests](/docs/guides/embedded-forms/embedded-data-requests/) need each host listed exactly, including any non-default port such as `localhost:3000`, and don't load when the list is blank.
- **Embed Edit Token**: Not shown in the embedded editor. The token you use with `template_editor.js` to embed this template editor. You can show or regenerate it. See [Embed Edit Token](/docs/guides/embedded-template-editor/#embed-edit-token).
- **Embedded Editor Permissions**: Not shown in the embedded editor. Allow embedded editor users to change template settings, to publish, restore, and delete versions, or to replace the PDF document. By default they can only edit fields and layout. See [Security](/docs/guides/embedded-template-editor/#security).
- **Predefined Fields**: _PDF templates only._ The field names that embedded editor users can add. See [Use Predefined Fields](/docs/guides/embedded-template-editor/use-predefined-fields/).

## Template PDF

_PDF templates only._ Shows the template's PDF file. Drop a new PDF onto the upload area to replace it.
