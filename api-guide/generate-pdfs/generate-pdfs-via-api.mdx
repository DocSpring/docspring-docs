DocSpring generates PDFs by filling your templates with submission data. Templates can either be uploads that you annotate in the Template Editor or fully custom HTML/CSS layouts that you host in DocSpring.

## Endpoint

```
POST /api/v1/templates/{template_id}/submissions
```

## Request Payload Basics

Every submission must include:

- `data`: Field values that match your template schema.

Optional parameters:

- `test`: Use `true` for free, watermarked PDFs while building your integration. Defaults to `false`. Live PDFs use [credits](/docs/billing/how-credits-work/); a request your balance can't cover returns `402` ([Credits & Rate Limits](/docs/api-guide/credits-and-rate-limits/)).
- `metadata`: Map of values you want echoed back in webhooks.
- `version`: Choose `draft`, `latest` (the default), or a specific version such as `1.2.3`.
- `editable`: Keep the resulting PDF fillable or flatten the form fields. See [Editable PDFs](#editable-pdfs).
- `expires_in`: Number of seconds until the submission expires. DocSpring then deletes the PDF, the submission data and metadata, and the submitter's IP address, browser and location. A submission that fails is kept for at least 48 hours.
- `password`: Encrypt the generated PDF with this password.
- `field_overrides`: Temporarily adjust field requirements or defaults.
- `data_requests`: Kick off a data collection or signature workflow before finalizing the PDF.

To choose between synchronous and asynchronous processing, use the `wait` query parameter (for example, `?wait=false`). It is not part of the JSON body. See [Processing Modes](#processing-modes).

## Processing Modes

Submissions sent to `sync.api.docspring.com` wait for processing and return the `download_url` in the response. Switching `wait=false` or using the asynchronous domain returns immediately with a pending submission. See [Sync vs. Async Processing](/docs/api-guide/synchronous-requests/) for the time limit, status checks, and webhook guidance.

## Editable PDFs

By default, DocSpring "flattens" generated PDFs into static text, so the fields cannot be changed. You can instead generate PDFs that keep editable form fields (AcroForm fields). Only Text and Check fields become form fields; other display types are always static.

There are two ways to control this:

- **Per submission:** Set `editable: true` in your submission request to make every field editable, or `editable: false` to flatten every field. An explicit value always takes precedence over the per-field option and the template setting below.
- **Per field:** Enable the "Editable" option on an individual field in the Template Editor. That field is rendered as an editable form field whenever the submission does not set the `editable` option.

Some templates (for example, older templates) have the "Generate Editable PDFs" template setting turned on. For these templates, every field is editable unless the submission sets `editable: false`.

Need to create many PDFs at once? Use the batch endpoint to submit up to 50 requests together. Each entry can target a different template, switch between test/live, and specify its own metadata.

## Forms from the DocSpring Form Library

The [form library](https://docspring.com/forms) has ready-made templates for common forms, such as IRS Form W-9. Each form's page shows its template ID. Send submissions to that template ID with your own API token, and they go into your account:

- The submissions and their PDFs are in your account, with your other submissions, and count toward your account's usage like your other PDFs. No other account can see them. The form doesn't count toward your plan's template limit.
- We keep the form up to date. Each request uses the latest version we've published, unless you set `version` to one of its published versions. You can't fill the draft we're working on: `"version": "draft"` returns a 404.
- Our settings for the form don't apply to your submissions: no webhook URL, Slack or email notifications, redirect URL or PDF encryption, and signers can't download the PDF from the signing page. Submissions expire as your account's default template settings say.
- Your account's webhooks get the `submission.*` and `submission_data_request.*` events. A webhook limited to some of your templates or folders doesn't, unless it's also limited to the API token you used. Your storage integrations upload the PDFs, except integrations limited to some of your templates or folders.
- If we take a form out of the library, you can't create new submissions with it. Your earlier submissions stay in your account.

To change the form or use your own settings, open it in the template editor (from the form's page, or from one of your submissions) and click **Copy to account**. The copy is your own template, with its own template ID, and we don't update it. If you find a problem with one of our forms, click **Send feedback** in the editor.

Batch requests and data requests work the same way. The form library is currently only available to accounts in our US region.
