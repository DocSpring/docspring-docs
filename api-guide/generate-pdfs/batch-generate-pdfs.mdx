Batch submission requests let you create multiple PDFs in parallel with a single call to the DocSpring API. Each item in the batch can point to a different template, supply different data, and choose between test or live mode.

## Endpoint

```
POST /api/v1/submissions/batches
```

## Request Structure

Provide an array of `submissions`. Each entry accepts `template_id`, `template_version`, `test`, `data` and `metadata` (plus `html` and `css` for HTML templates). Batch entries don't support the other options of a single submission request, such as `data_requests`, `editable`, `expires_in` or `field_overrides`.

You can also set `template_id`, `template_version` (default `latest`) and `test` at the top level of the request. They apply to every entry that doesn't set its own value. A top-level `metadata` object is saved on the batch itself.

```json
{
  "submissions": [
    {
      "template_id": "tpl_contract",
      "data": { "name": "John Smith" },
      "test": true,
      "metadata": { "pdf_filename": "contract_draft_john_smith" }
    },
    {
      "template_id": "tpl_invoice",
      "data": { "name": "Acme Corp" },
      "test": false
    }
  ]
}
```

<Aside type="tip">
  Use metadata fields like <code>pdf_filename</code> or <code>pdf_title</code>{" "}
  on individual submissions to keep generated files organized.
</Aside>

## Response Format

By default, the API waits until every PDF in the batch has been processed. The response includes the `submission_batch` and a `submissions` array with one submission for each entry, in the same order as your request:

```json
{
  "status": "success",
  "submission_batch": {
    "id": "sbb_1234567890abcdef01",
    "state": "processed",
    "metadata": {},
    "processed_at": "2024-02-01T12:00:05Z",
    "total_count": 2,
    "pending_count": 0,
    "error_count": 0,
    "completion_percentage": 100
  },
  "submissions": [
    {
      "id": "sub_1234567890abcdef01",
      "state": "processed",
      "download_url": "https://..."
    },
    {
      "id": "sub_1234567890abcdef02",
      "state": "processed",
      "download_url": "https://..."
    }
  ]
}
```

_(Other submission fields are left out here.)_

When you add `?wait=false` to the request URL, the API responds straight away, and each item in `submissions` wraps the submission with its own `status`:

```json
{
  "status": "success",
  "submission_batch": { "id": "sbb_1234567890abcdef01", "state": "pending" },
  "submissions": [
    {
      "status": "success",
      "submission": { "id": "sub_1234567890abcdef01", "state": "pending" }
    }
  ]
}
```

You can then check the batch with `GET /api/v1/submissions/batches/{submission_batch_id}?include_submissions=true` until its `pending_count` is `0`, or listen for the batch webhooks. DocSpring sends `submission_batch.processed` when every PDF has been generated, or `submission_batch.failed` instead if any of them failed.

If any entry fails validation, DocSpring doesn't generate any of the PDFs in the batch. The API responds straight away with HTTP status `200` and `"status": "error"`, using the same wrapped items. Valid entries have `"status": "valid_but_not_saved"`, and invalid entries have `"status": "error"` with a list of `errors`. Fix the invalid entries and send the whole batch again.

Some problems are reported with a `4xx` status and a single `error` message instead, such as more than 50 entries, an unknown template ID, or an entry without a `data` object.

## Limits & Best Practices

- **Up to 50 submissions** per batch request.
- **Mix templates freely** – each item can target a different template.
- **Test vs. live mode** – set `test` per submission.
- **Back pressure** – prefer batch requests when generating many documents to avoid hitting rate limits with individual calls.
- **Webhooks** – enable webhooks if you need to know when asynchronous submissions finish processing.
