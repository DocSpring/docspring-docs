DocSpring supports two different kinds of templates:

- **PDF templates**: Upload an existing PDF and add fields using the template editor.
- **HTML/CSS templates**: Create a new template from scratch using HTML and CSS.

## SASS

Our HTML/CSS templates use a CSS extension called [SASS](http://sass-lang.com/).
We use the version that is compatible with standard CSS (SCSS).

This means that you can paste in any CSS, and it will Just Work&trade;.
SCSS also supports some powerful features, including variables and nested rules.
Take a look at the [SASS Guide](http://sass-lang.com/guide#topic-2) to learn more.

## Liquid

HTML templates use the [Liquid markup language](https://shopify.github.io/liquid/basics/introduction/).
This allows you to insert field values into your HTML. You can also add advanced logic,
such as [conditions](https://shopify.github.io/liquid/tags/control-flow/) and
[loops](https://shopify.github.io/liquid/tags/iteration/).

[Learn more about Liquid](https://shopify.github.io/liquid/basics/introduction/).

### Referencing Fields

Use the `{{ }}` syntax to insert a field value in your template.

If you have a field called "name", you can render that value in your template like this:

```html
<h2>{{ name }}</h2>
```

Use a dot to access nested fields, and square brackets for arrays:

```html
<h2>{{ person.name }}</h2>
<h2>{{ names[2] }}</h2>
```

### HTML Escaping

The template's **Escape HTML in Data** setting decides how values are printed. It's on for new templates. Templates
created before October 2026, or with API v1, have it off. Change it in the template's settings, or with
`html_escape_data` when you [update the template](/docs/api/#tag/templates/put/templates/{template_id}).

When it's on, `{{ value }}` prints a value as text: a `<` or `&` in it shows as that character, and can't add HTML to
the page. Use the `raw` filter for a value that holds HTML you trust:

```html
<p>{{ customer_notes }}</p>
<div>{{ terms_html | raw }}</div>
```

Put `raw` last: a filter after it escapes what it adds. The `escape` and `newline_to_br` filters work as before and
never escape a value twice, so `{{ notes | escape | newline_to_br }}` prints the same with the setting on or off.

When it's off, every value is printed as HTML, as it is. Use `{{ value | escape }}` for text that could contain `<` or
`&`. Before you turn the setting on for a template, add `| raw` to the values that hold HTML.

### Liquid Filters

When you upload an existing PDF, our template editor includes features such as date formatting,
formulas for numbers, "uppercase" for text fields, etc. These features have been removed from our HTML template editor,
because these can be achieved by using Liquid "filters".

For example, you can use the `upcase` filter to convert text to uppercase:

```html
<h2>{{ full_name | upcase }}</h2>
```

[See the Liquid Filters page for more information about available filters.](/docs/html-templates/liquid-filters/)

Please [contact us](mailto:support@docspring.com) if you would like us to add a new Liquid filter.

<Aside type="note">
  DocSpring supports most of the Liquid filters that you can find in [the Liquid
  documentation](https://shopify.github.io/liquid/). However, you may find some
  third-party articles and documentation that reference filters that we don't
  support. For example,
  [Shopify](https://shopify.dev/docs/themes/liquid/reference) provides some
  custom liquid filters that are specific to Shopify stores.
</Aside>

### Signatures

You must use the `{% signature %}` Liquid tag to render signatures in your HTML template.
Signatures can be provided as either an image, or text (e.g. the user typed their name and selected a font). The `signature` tag will handle both of these cases:

```html
{% signature signature_field %}
```

Behind the scenes, image signatures will be rendered in an `<img>` element with a `signature-image` class:

```html
<img class="signature-image" src="data:image/png;base64,..." />
```

Text signatures will import the required typeface, and render the `name` inside a `<span>` element with a `signature-text` class:

```html
<link
  href="https://fonts.googleapis.com/css?family=Dancing+Script"
  rel="stylesheet"
/>
...
<span
  class="signature-text"
  style="color: black; font-size: 16px; font-weight: normal; display: inline-block; font-family: 'Dancing Script';"
>
  John Smith
</span>
```

You can pass the following options to the `signature` tag, to control the width and height of image signatures, or the font size and weight of text signatures. (These options are added as inline CSS styles.)

| Option        | Signature Type | Default Value  |
| ------------- | -------------- | -------------- |
| `width`       | Image          | `(from image)` |
| `height`      | Image          | `(from image)` |
| `font-size`   | Text           | `16px`         |
| `font-weight` | Text           | `normal`       |
| `color`       | Text           | `black`        |

There is also a `preview_type` option, which allows you to control the type of signature that is shown in preview PDFs. We show an image signature by default. Use `preview_type: text` to show a text signature.

Examples:

```html
{% signature signature_field, width: 300px %}
```

```html
{% signature signature_field, preview_type: text, font-size: 24px, color: #333
%}
```

### Initials

You must use the `{% initials %}` Liquid tag to render initials in your HTML template.
Initials behave exactly like signatures — they can be provided as an image or as text, and the `initials` tag handles both cases:

```html
{% initials initials_field %}
```

Image initials are rendered in an `<img>` element with an `initials-image` class:

```html
<img class="initials-image" src="data:image/png;base64,..." />
```

Text initials will import the required typeface and render the initials inside a `<span>` element with an `initials-text` class:

```html
<link
  href="https://fonts.googleapis.com/css?family=Dancing+Script"
  rel="stylesheet"
/>
...
<span
  class="initials-text"
  style="color: black; font-size: 16px; font-weight: normal; display: inline-block; font-family: 'Dancing Script';"
>
  JS
</span>
```

The `initials` tag accepts the same options as the `signature` tag:

| Option        | Initials Type | Default Value  |
| ------------- | ------------- | -------------- |
| `width`       | Image         | `(from image)` |
| `height`      | Image         | `(from image)` |
| `font-size`   | Text          | `16px`         |
| `font-weight` | Text          | `normal`       |
| `color`       | Text          | `black`        |

Use the `preview_type` option to control how initials appear in preview PDFs. Preview image initials are shown by default. Use `preview_type: text` to display text initials instead.

Examples:

```html
{% initials initials_field, width: 100px %}
```

```html
{% initials initials_field, preview_type: text, font-size: 18px, color: #333 %}
```

### Images

You can upload static images under the "Images" tab. Use the `template_image_url` tag to get
the image URL:

```html
<img src="{% template_image_url IMAGE_ID %}" />
```

To include an image or barcode field (i.e. submitted in an API request),
you can use the field value as the `src` attribute for an `img` tag.
This will refer to an internal URL for the image:

```html
<img src="{{ photograph }}" />
```

If you have an optional image field, you should use a condition in case the image was not provided:

```html
{% if photograph %} <img src="{{ photograph }}" /> {% endif %}
```

### Dates

You can use the `date` filter to format a date field:

```html
<h2>{{ date | date: "%B %-d, %Y" }}</h2>
```

You can use the special `"now"` string to get the current date and time:

```html
<h2>{{ "now" | date: "%B %-d, %Y" }}</h2>
```

We also support an `in_time_zone` filter that allows you to convert dates and times into different timezones:

```html
<h2>{{ "now" | in_time_zone: "America/New_York" | date: "%B %-d, %Y" }}</h2>
```

[Here is a list of timezones that you can use with the `in_time_zone` filter.](/docs/html-templates/liquid-timezones/)

### Metadata

You can use the `metadata` tag to access metadata from your submission:

```html
<h2>{% metadata foo %}</h2>
```

### Template Details

You can use the `template` tag to access data about your template:

```html
<h2>{% template id %}</h2>
<h2>{% template name %}</h2>
<h2>{% template version %}</h2>
<h2>{% template version_published_at %}</h2>
```

## Page Settings

Click the "Settings" button in the header to set up the pages of an HTML/CSS template:

- _Page Format_: Letter (the default), Legal, Tabloid, Ledger, CR80, A0, A1, A2, A3, A4, A5, A6, or Custom.
  Check _Landscape_ to use a landscape page (not available for Custom).
- _Page Size_: The width and height of a Custom page (defaults to `8.5in` by `11in`).
- _Page Margins_: The top, bottom, left, and right margins (each defaults to `1in`). Set the margins to 0 to remove
  the white border around the page.
- _Print Background_: Renders backgrounds that your CSS sets (unchecked by default). Backgrounds aren't drawn over the
  page margins.

Sizes and margins can use `px` (pixels), `in` (inches), `cm` (centimeters), or `mm` (millimeters). Give each one a
unit, such as `1in` or `20mm`: only `0` can go without one.

## Page Breaks

You can force content to start on a new page by using the `page-break-before` CSS property.

<Tabs>
  <TabItem label="CSS">
    ```css
    .new-page {
      page-break-before: always;
    }
    ```
  </TabItem>
  <TabItem label="HTML">
    ```html
    <p class="new-page">This paragraph will start on a new page.</p>
    ```
  </TabItem>
</Tabs>

[View documentation for the page-break-before, page-break-after, and page-break-inside properties](https://developer.mozilla.org/en-US/docs/Web/CSS/page-break-before).

## Headers and Footers

You can add a header or footer to each page in the
"Header HTML" and "Footer HTML" tabs. CSS from the _SCSS_ tab also applies
to headers and footers.

You can use the `pageNumber` and `totalPages` classes to show the current page number and total pages. The following example shows how to add a footer with page numbers
(e.g.&nbsp;_Page&nbsp;1&nbsp;of&nbsp;2_):

```html
<footer
  id="footer"
  style="display: block; margin: 0 40px; padding-top: 3px; width: calc(100% - 80px); border-top: 1px solid #aaa; color: #aaa; text-align: right;"
>
  <div>
    Page&nbsp;<span class="pageNumber"></span>&nbsp;of&nbsp;<span
      class="totalPages"
    ></span>
  </div>
</footer>
```

<Aside type="tip">
  The footer will appear at the bottom of each page with page numbers like "Page
  1 of 2".
</Aside>

Headers and footers can't load anything from the network. A header or footer with a stylesheet (a `<link>` tag or an
`@import`), a font from a URL, or a typed signature (which loads a Google Font) fails with "The header or footer
couldn't be printed". Put their CSS in a `<style>` tag, use a font that's installed or embedded as a `data:` URL, and
keep signatures in the body.

## Limits

- **Generated PDF:** up to 500 MB. Photos embedded at full camera resolution can go over this. Resize images to the
  size they are displayed at.
- **Template HTML:** up to 50 MB for the body HTML, and 5 MB each for the header HTML, the footer HTML and the SCSS.
  The other limits are in [Size limits](/docs/api-guide/size-limits/).
- **Rendered HTML:** up to 128 MB in total for the body, header and footer HTML once your data is filled in, including
  any images embedded in it as base64.
- **Header and footer images:** up to 25 MB each. They are embedded into the header or footer HTML.
- **[Image field](/docs/reference/field-data-types/#image) values given as a URL:** up to 100 MB each.

A document over one of these limits fails with an error that names the limit, and isn't retried. A very large
document can also take too long to render, and often does before its PDF reaches 500 MB. A render that runs out of
time is retried a few times before it fails.

## Previewing with Data

A [preview](/docs/api/#tag/templates/post/templates/{template_id}/previews) returns PNG images of a template's pages printed with the data you send, not a PDF, so you can check how the template prints with your data before you publish it or send live data. DocSpring renders the template's draft (or a published version) with the data and returns an image of each page. A preview makes no submission and uses no credits, and its pages are watermarked like a test PDF's. Previews work for PDF templates too. The [MCP server](/docs/mcp/)'s `preview_template` tool does the same for AI agents.

## Generating PDFs

Once you've set up your template and added your fields, you can generate a PDF by either filling out the [web form](/docs/forms/web-forms/), or [making an API request](/docs/api/#tag/submissions/post/templates/{template_id}/submissions). [Create an HTML Template with the API](/docs/html-templates/create-with-the-api/) walks through every step with `curl`.
